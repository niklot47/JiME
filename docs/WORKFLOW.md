  - `D:\JiME_Claude\data\ref\Снимки экрана\` — скриншоты оригинала (1920×1080, по порядку игры), уменьшенные копии с номерами — `data\ref\small\01..32.jpg`;

## Кто что делает

| Задача | Где | Почему |
|---|---|---|
| Импорт из игры, экспорт JSON | ПК (Linux-VM рабочей среды, `device_bash`) | Файлы игры на месте, без загрузки сотен МБ |
| Прогоны движка, фаззер, тесты (Python, позже `npm test`) | ПК (VM) | Данные рядом, результат сразу в репозитории |
| Правка кода | ПК (VM): Claude правит файлы на месте | Без пересылки файлов туда-обратно |
| `git commit` | ПК, сам пользователь или Claude после разрешения на удаление (git удаляет lock-файлы) | См. ниже |
| Сборка Tauri / Windows-exe, `npm run dev` с окном | **Пользователь на Windows** (PowerShell) | VM — это Linux, оконные приложения Windows там не собрать |
| Посмотреть картинку или скриншот, рендер в headless Chromium | Облако | Только там Claude видит изображения и есть Chromium |
| Тяжёлые эксперименты, сторонние инструменты, которые не ставятся на ПК | Облако | Изолированно, с полной сетью |
| Публикация страниц/артефактов | Облако, **только без контента FFG** | Графику и тексты FFG не распространяем |

Ограничения VM на ПК:
- каждый вызов не дольше ~3 мин, оболочка свежая;
- пакеты ставятся через `tools/env.sh` в начале каждой сессии;
- удаление файлов в подключённых папках запрещено, пока пользователь не разрешит это в запросе;
- `node_modules` **не ставить в репозиторий из VM**: там Linux-симлинки и бинарники. JS-команды в VM — через `bash tools/vm-node.sh <script>`: зеркалирует код в `$HOME/jime_build`, ставит зависимости там и возвращает `pnpm-lock.yaml`. На Windows — обычный `pnpm install` в репозитории.

## Как экономить токены

1. **Не гонять данные через чат.** Скрипты пишут результаты в файлы (`data/out/...`), в чат печатается только сводка (≤30 строк).
2. **Не перечитывать большие файлы целиком.** Использовать `grep`/`head`, точечные чтения, JSON-запросы через python.
3. **Работать на ПК, а не стейджить файлы в облако.** Стейджить только то, что Claude должен *увидеть* (картинки) или то, что не может обработать VM.
4. **Начало сессии = 2 файла:** `docs/ROADMAP.md` (где мы) и при необходимости раздел `docs/NOTES.md`. Не пересказывать историю.
5. **Конец сессии:** обновить «Журнал» в `ROADMAP.md`, сделать коммит.
6. **Субагенты и воркфлоу** запускать только по явной просьбе: они дорогие.
7. **Большие задачи дробить на этапы с проверкой** (тест или прогон бота), чтобы не переделывать.

## Справочники: что где искать

| Что нужно | Где |
|---|---|
| Как ведёт себя окно, кнопка, анимация, что показывается когда | декомпилированный код: `Декомпилированые файлы/Assembly-CSharp/FFG.JIME/…`, `FFG.Common/…` (например `MessagePopup.cs`, `MessageButtonController.cs`, `SlidingElement.cs`, `TitleLogoAnimation.cs`, `StartUpMenuController.cs`, `UIThreatMeter.cs`, `EnemyMenu.cs`). Искать: `grep -rn "<имя>" "$HOME/mnt/JiME_Claude/Декомпилированые файлы/Assembly-CSharp"` |
| Разметка интерфейса (позиции, размеры, спрайты, цвета, шрифты, твины) | выгрузка `data/packs/core-ffg/images/ui/layouts/ui.json` (`tools/importer/export_ui_layouts.py`); просмотр в приложении: главное меню → «Интерфейс»; без игры: `python tools/importer/ngui_render.py <id GameObject>` (PNG в `data/out/ngui/`), дерево: `ngui_walk.py <id>` |
| Как это выглядит на экране | `data/ref/Снимки экрана/`, `data/ref/small/` |
| Как это движется (анимации, эффекты, порядок) | `data/ref/video/` — **анимации и эффекты отложены**, к ним вернуться после переноса разметки |
| Значения из сцен и моделей (любой MonoBehaviour) | `tools/importer/jload.py`: `read_mb(obj)`, `mbs_of("FFG.JIME.<Класс>")` |

Правило для разметки: многие элементы сохранены в сцене в **начальной точке своей анимации появления** (выезжают из-за края, растут из 0.7 и т. п.). `ngui/solve.ts` рисует одноразовые твины (style 0) в конечном состоянии, если сохранённое значение совпадает с их началом; точное поведение (скрипты, которые переписывают from/to перед проигрыванием, как `TitleLogoAnimation`) — по декомпилированному коду.

Проверка окна приложения: `pnpm tauri dev` с `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9222"`, затем `node tools/dev/cdp.mjs <скрипт.js> <префикс>` (скриншоты, `ev`, `send`); примеры скриптов — `tools/dev/cdp-*.js`.

## Git

- Репозиторий: `D:\JiME_Claude`. В `.gitignore`: `data/`, `Декомпилированые файлы/`, `node_modules/`, сборки, всё с контентом FFG.
- Коммитит Claude через Desktop Commander (`start_process`, PowerShell прямо на Windows): `cd D:\JiME_Claude; git add -A; git commit -m "..."`. Пушит тоже Claude (`git push`); если пуш не прошёл — сообщить пользователю. Из VM git не работает: папка `.git` там не видна.
- Сборка и запуск Tauri на Windows тоже может делать Claude через Desktop Commander (`cargo` — `%USERPROFILE%\.cargo\bin`, его нет в PATH оболочки). Окно проверяется без скриншотов экрана: запуск с `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222` и `node tools/dev/cdp.mjs <скрипт>`. Запущенные процессы (`jime-app`, `node`, `cargo`) потом остановить.
- Заметка для Claude: `device_commit_files` с тем же `stagedPath`, что уже коммитился, может записать старую версию файла — для повторной записи брать новое имя в outputs или править на ПК через `device_bash`.
- `.gitignore`: `/data/` — только корневая папка (раньше `data/` скрывал и `apps/app/src/data`).
- Позже можно завести приватный репозиторий на GitHub: тогда облачная сессия сможет клонировать код без ПК.
