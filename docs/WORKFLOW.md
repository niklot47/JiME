# Рабочий процесс: ПК пользователя ↔ облако Claude

## Где что живёт

- **Источник истины — `D:\JiME_Claude` на ПК пользователя** (git-репозиторий). Облачная среда Claude временная: всё, что не записано сюда или в проект claude.ai, пропадает с концом сессии.
- **Игра** — `D:\SteamLibrary\steamapps\common\Journeys in Middle-earth`. Импортёр читает её напрямую, ничего не копируя и не загружая в облако.
- **Проект claude.ai «Journey in Middle Earth»** — короткие заметки и копии скриптов на случай, если ПК недоступен. Основная копия всё равно на ПК.

## Кто что делает

| Задача | Где | Почему |
|---|---|---|
| Импорт из игры, экспорт JSON | ПК (Linux-VM рабочей среды, `device_bash`) | Файлы игры на месте, без загрузки сотен МБ |
| Прогоны движка, фаззер, тесты (Python, позже `npm test`) | ПК (VM) | Данные рядом, результат сразу в репозитории |
| Правка кода | ПК (VM): Claude правит файлы на месте | Без пересылки файлов туда-обратно |
| `git commit` | ПК, сам пользователь или Claude после разрешения на удаление (git удаляет lock-файлы) | См. ниже |
| Сборка Tauri / Windows-exe, `npm run dev` с окном | **Пользователь на Windows** (PowerShell) | VM — это Linux, оконные приложения Windows там не собрать |
| Посмотреть картинку или скриншот, рендер в headless Chromium | Облако | Только там Claude видит изображения и есть Chromium |
| Тяжёлые эксперименты, сторонние инструменты, которые не ставятся на ПК | Облако | Изолированно, с полной сетью |
| Публикация страниц/артефактов | Облако, **только без контента FFG** | Графику и тексты FFG не распространяем |

Ограничения VM на ПК:
- каждый вызов не дольше ~3 мин, оболочка свежая;
- пакеты ставятся через `tools/env.sh` в начале каждой сессии;
- удаление файлов в подключённых папках запрещено, пока пользователь не разрешит это в запросе.

## Как экономить токены

1. **Не гонять данные через чат.** Скрипты пишут результаты в файлы (`data/out/...`), в чат печатается только сводка (≤30 строк).
2. **Не перечитывать большие файлы целиком.** Использовать `grep`/`head`, точечные чтения, JSON-запросы через python.
3. **Работать на ПК, а не стейджить файлы в облако.** Стейджить только то, что Claude должен *увидеть* (картинки) или то, что не может обработать VM.
4. **Начало сессии = 2 файла:** `docs/ROADMAP.md` (где мы) и при необходимости раздел `docs/NOTES.md`. Не пересказывать историю.
5. **Конец сессии:** обновить «Журнал» в `ROADMAP.md`, сделать коммит.
6. **Субагенты и воркфлоу** запускать только по явной просьбе: они дорогие.
7. **Большие задачи дробить на этапы с проверкой** (тест или прогон бота), чтобы не переделывать.

## Git

- Репозиторий: `D:\JiME_Claude`. В `.gitignore`: `data/`, `Декомпилированые файлы/`, `node_modules/`, сборки, всё с контентом FFG.
- Коммиты удобнее делать самому в PowerShell (`git add -A; git commit -m "..."`). Если коммитит Claude из VM, ему нужно разрешение на удаление в папке `JiME_Claude`: git удаляет свои lock-файлы.
- Позже можно завести приватный репозиторий на GitHub: тогда облачная сессия сможет клонировать код без ПК.
