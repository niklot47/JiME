# Движок (`packages/engine`)

Интерпретатор сценариев FFG: семантика PlayMaker FSM поверх prefab-данных, плюс упрощённые поле, враги и раунды.
Без UI и без Node-зависимостей в ядре: данные приходят через интерфейс `ContentSource`.

## Файлы

| Файл | Что |
|---|---|
| `src/game.ts` | `Fsm`, объекты сцены (`Obj`, `Tile`, `GameNode`, `EnemyGroup`), `Game` (сцена, карта, маршрутизация событий, раунды), `Bot` |
| `src/actions.ts` | Обработчики действий FSM: имя действия PlayMaker → поведение |
| `src/pyrandom.ts` | ГСЧ, бит-в-бит совместимый с Python `random.Random` (MT19937) |
| `src/ojson.ts` | JSON-парсер с сохранением порядка числовых ключей (`keysOf`/`valuesOf`) |
| `src/py.ts` | Семантика Python: истинность, `str()`, `int()`, `dict.get` |
| `src/map/mapgen.ts` | Генератор карты — порт MapBuilder/SectionBuilder FFG (Этап 2.3) |
| `src/map/netrandom.ts`, `netsort.ts`, `hex.ts` | .NET `System.Random`, интросорт .NET `List.Sort`, кубические координаты гексов |
| `src/session.ts` | Интерактивная игра: решения игрока, реплей, сохранение/загрузка, отмена, снимок для UI |
| `src/node/packSource.ts` | Чтение пака с диска (только Node) |
| `cli/run.ts` | Одна партия бота, лог формата LogA |
| `cli/fuzz-all.ts` | Все приключения × N сидов: ошибки, покрытие, предупреждения |
| `cli/parity.ts` | Сверка с `engine-py` по тем же сидам |
| `cli/replay-check.ts` | Партии бота → ответы → реплей через Session, плюс сохранение/загрузка/отмена |
| `cli/mapgen.ts` | Сгенерировать карту: `node cli/mapgen.ts <adv> <seed> [игроки] [--products 0] [--used …] [--items …]` |
| `cli/play.ts` | Текстовая игра в терминале (ru/en/it) — первый «человеческий» клиент Session |

## Паритет с Python (Этап 2.1)

TS-движок — построчный перенос `engine-py/engine.py`. Одинаковое поведение при одном сиде:

- ГСЧ совместим с CPython;
- словари обходятся в порядке файла, как в Python;
- истинность и приведения — по правилам Python.

`pnpm parity` сравнивает:

- полный лог;
- исход, раунд, угрозу;
- предупреждения и нереализованные действия;
- покрытие состояний FSM;
- итог кампании.

Результат на 13.10.2026: **3315 из 3315 партий идентичны** (72 приключения × 35 сидов + A1–A3 × 265 сидов).

### Правила

- Пока `engine-py` — эталон, семантику менять **в обоих движках сразу** и прогонять `pnpm parity`.
- Когда TS начнёт уходить вперёд (точная карта, бой — Этап 2.3), `engine-py` замораживается, а паритет заменяется собственными тестами и фаззером.
- Тесты в `test/` используют синтетические сценарии: в CI нет данных FFG.

## Интерактивная игра: Session (Этап 2.2)

Интерпретатор синхронный, а вопросы игроку возникают глубоко внутри цепочки событий FSM.
Поэтому пауза сделана через **детерминированный реплей**, а не через остановку стека.

- Все решения игроков идут через интерфейс `Player`:

  | Решение | Ответ |
  |---|---|
  | проверка | число успехов |
  | подтверждение | да/нет |
  | выбор варианта | номер или отмена |
  | выбор героя | номер героя, пропуск |
  | последний рубеж | да/нет |
  | действие героя | номер варианта или «закончить ход» |
  | урон по врагу | число |

- `Bot` — одна из реализаций `Player`.
- `ScriptedPlayer` отвечает из списка. Когда список кончился, бросает `NeedInput(decision)`.
- `Session` хранит настройки и список ответов:
  - `pending` — текущий вопрос (простой JSON для UI);
  - `answer(a)` — дописать ответ и перепроиграть партию с нуля (~6 мс на 127 решений);
  - `undo(n)` — отменить ответы;
  - `save()` / `Session.load()` — сохранение: настройки + ответы, несколько КБ;
  - `view()` — снимок видимого состояния.
- Требование детерминизма: движок не меняет исходные данные пака (переопределение порога угрозы хранится в `Obj.threatThreshold`). Счётчики id — свои у каждой партии.
- Бот по умолчанию делит ГСЧ с игрой — так нужно для паритета с Python. Для записи ответов (`recordBotGame`) бот получает собственный ГСЧ, иначе при реплее не хватит его случайных бросков.
- Сохранение действительно для той версии движка, в которой сделано (`engine` в файле). Миграции — позже.

Проверка (`node packages/engine/cli/replay-check.ts 3`):

- 216 из 216 партий (72 приключения × 3 сида);
- запись бота → реплей, сохранение на середине → загрузка → доигрывание → отмена → повтор;
- везде лог идентичен.

## Генератор карты (Этап 2.3)

Точный порт `MapBuilder` + `SectionBuilder` из декомпиляции (алгоритм переписан, код FFG не копировался):

- ГСЧ — .NET `System.Random`, совпадает с Mono бит в бит (векторы в `test/netvectors.json`);
- `List.Sort` — интросорт .NET: он неустойчив, и результат FFG зависит от порядка равных элементов;
- float32-арифметика коэффициентов через `Math.fround`;
- геометрия тайлов — `db.tiles`: гексы, клетки, внешние рёбра с типами (дорога, вода, проход…), в порядке корзины StandardTiles сцены level4. Кастомные тайлы приключений лежат в `ext.customTiles`;
- владение продуктами, язык (часть встреч недоступна на некоторых языках), история кампании (использованные встречи и группы, цепочки, инвентарь отряда);
- выход: секции → тайлы с поворотом и глобальными координатами гексов, встречи по клеткам, порядок спавна, связи клеток.

**Сверка с оригинальной игрой** (`SavedGames/BuildDump.dat` + сохранения, версия 1.6.6):

| Генерация | Что совпало |
|---|---|
| A1, сид 1140143612, 3 игрока, новая кампания | все 15 встреч **в том же порядке** (`UsedEncounterIds`), группа 6 |
| A3, сид 248115147, 3 игрока, после A1–A2, у отряда предмет 58 | все 18 новых встреч в том же порядке, группа 3 |
| A1, сид −1893041487 (лог 2023 г., версия 1.5.4) | тайлы всех секций; встречи отличаются — в 1.5.4 был другой пул |

Время. Оригинал реагирует на реальное время: через 5 с без улучшения откатывает раскладку секций, через 6 с прерывает постройку и берёт сид+1 (таймаут растёт на 6 с с каждой попыткой). У нас вместо часов детерминированный счётчик работы: 100 тыс. примерок = 1 с (оценка скорости оригинала). Быстрые постройки (почти все) точные; патологические сиды ведут себя как на типичном устройстве. Проверка на 984 картах (39 приключений × 8 сидов × 1/3/5 игроков): все строятся, 5 % — со второй попытки, в среднем 75 мс. Исключение — A27 на одного игрока: в секции «First Wilds» 5 обязательных встреч при максимуме 4 клетки. Это ограничение данных FFG, не порта.

В игре: `mapMode: "ffg"` по умолчанию, если в паке есть геометрия; `"legacy"` — упрощённый генератор engine-py для сверки с Python. Сид карты — `mapSeed` (по умолчанию сид партии). Session генерирует карту один раз и переиспользует её в реплеях.

Ещё не проверено: позиции и повороты тайлов. Для проверки нужно сохранение посреди приключения из оригинала — в нём есть `Tiles[].LocalRotations` и `StartHexGlobalCoord`.

## Команды

```bash
pnpm play 1 7          # сыграть самому в терминале: A1, сид 7 (--lang en, --load файл)
pnpm play:bot 1 7      # та же партия ботом, лог LogA
pnpm fuzz              # 72 приключения × 10 сидов (~10 с)
pnpm parity            # сверка с Python, 72 × 5 сидов (карта legacy)
node packages/engine/cli/mapgen.ts 1 1140143612 3   # карта как в оригинале
node packages/engine/cli/parity.ts 1,2,3 0 300   # выборочно
```
